## Phase Goal

**As a** child playing on a phone, **I want to** walk around the Forest tile map with a big D-pad or the keyboard, **so that** exploring feels responsive and I can find tall grass.

**This plan's slice:** the phase goal becomes real on screen. After Task 3 a player can open `/game`, press the D-pad or an arrow key, and watch the player walk the Forest and get blocked by trees. Motion polish (200ms tween, camera easing, walk frames) is refined in 03-03.

<objective>
Put the 03-01 movement core on screen: one shared held-direction input path for keyboard and touch, a coarse Zustand explore store, an imperative rAF loop, and the Forest map/player render layer composed into `GameScreen`.

Purpose: MAP-01 requires the D-pad and keyboard to funnel through one input path; MAP-02 requires pixelated tiles with the player centred; MAP-04 requires that no pixel value ever passes through React state. This plan is the first point at which the phase goal is playable.
Output: `store/exploreStore.ts`, `hooks/{usePlayerInput,useExploreLoop}.ts`, `components/controls/DPad.tsx`, `components/map/{MapViewport,TileWorld,PlayerSprite}.tsx`, rewritten `screens/GameScreen.tsx`, `.dpad-target` utility, and the integration tests that prove walking works.
