## Phase Goal

**As a** child playing on a phone, **I want to** walk around the Forest tile map with a big D-pad or the keyboard, **so that** exploring feels responsive and I can find tall grass.

**This plan's slice:** the last two things a player or the next phase would notice — grass that quietly registers something happened (without a single pixel of encounter UI), and a screen that recovers gracefully if the map data is broken. This plan also locks the Phase 3/Phase 4 boundary with tests so encounter work cannot leak backwards.

<objective>
Finish the Phase 3/Phase 4 seam and the explore screen's failure path: a bounded `encounter_candidate` queue with a documented single read point, a DEV-only emission log, map integrity validation feeding the "Map didn’t load" recovery card, and automated guards asserting that no encounter rolls, tables, or UI exist.

Purpose: the CONTEXT decision requires grass to emit an event that Phase 4 subscribes to while explicitly forbidding encounter UI, rolls, or tables in this phase. The seam needs to be discoverable and bounded, and the boundary needs a test that fails loudly if a later change crosses it.
Output: extended `game/events.ts` and `game/collision.ts`, bounded store queue, DEV log in the loop, `GameScreen` error recovery, and the seam/boundary/error tests.
</objective>
