## Phase Goal

**As a** child playing on a phone, **I want to** walk around the Forest tile map with a big D-pad or the keyboard, **so that** exploring feels responsive and I can find tall grass.

> Derived from the ROADMAP Phase 3 `**Goal**` line ("Player can walk a tile map that feels responsive on a phone") plus Success Criteria 1–3. The ROADMAP line is not yet stored in user-story form; no scope was added or removed in this restatement.

**This plan's slice:** the rules of walking. After this plan the walking behaviour a player will feel — one tile per press, blocked by trees, grass noticed — exists and is provable by test, with no UI yet. Plan 03-02 puts it on screen.

<objective>
Create the pure `game/` movement core for Forest exploration: typed map contracts, the Forest map data, bounds-checked collision, and discrete tile stepping that emits an `encounter_candidate` event when the player steps onto grass.

Purpose: MAP-04 requires movement and collision to resolve in pure `game/` logic rather than per-frame React state. Locking the rules and their tests first means the render layer in 03-02 only translates state into pixels, and Phase 4 gets a stable event seam.
Output: `types/map.ts`, `data/exploreConfig.ts`, `data/maps/forest.ts`, `game/{collision,movement,events}.ts` plus the three Wave 0 test files from 03-VALIDATION.md.
</objective>

- `completeStep(state)` returns `{ ...state, moving: false }`.
