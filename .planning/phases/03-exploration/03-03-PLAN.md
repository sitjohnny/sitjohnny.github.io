## Phase Goal

**As a** child playing on a phone, **I want to** walk around the Forest tile map with a big D-pad or the keyboard, **so that** exploring feels responsive and I can find tall grass.

**This plan's slice:** the same walking, now feeling right. The instant-teleport steps from 03-02 become 200ms glides with a smoothly trailing camera, a walking sprite, and a reduced-motion path that keeps every control working.

<objective>
Replace 03-02's instant step and hard-centred camera with the Emerald-style motion contract: a `STEP_DURATION_MS` tile tween, exponential camera follow clamped to the map bounds, and a walk-frame cycle on the player sprite — all driven by refs inside the existing rAF loop.

Purpose: MAP-02 requires the camera to follow the player with pixelated tiles; the CONTEXT decision requires eased camera smoothing rather than hard-locked snapping. MAP-04 requires that adding motion adds zero React re-renders. The camera math is pure so it is unit-testable (03-VALIDATION.md Wave 0 `camera.test.ts`).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| rAF timestamps → camera math | Frame deltas are environment-controlled and can spike after a background tab or slow device |
| viewport measurement → transform | `getBoundingClientRect` values feed clamping arithmetic and can be zero during layout |
| React tree → DOM | The loop writes transforms and `data-frame` directly on nodes React owns |
