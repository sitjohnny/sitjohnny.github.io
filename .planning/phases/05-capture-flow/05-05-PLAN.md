## Phase Goal

**As a** child who finished the math question, **I want to** throw with a timing bar and catch the Pokémon (or see it flee kindly after three tries), **so that** commons feel easy to catch and legendaries stay exciting.

**This plan's slice (gap closure):** every throw — not just the first — shows the timing grade flash BEFORE the ball shake, so the child always sees how well they timed the throw before learning the outcome (restores D-14 / VERIFICATION Truth #8; hardens the mash-lock store invariant per WR-03).

**Gap-closure scope note:** This plan closes the single BLOCKER from 05-VERIFICATION.md plus one cheap adjacent hardening from 05-REVIEW.md (WR-03). Do NOT touch already-verified behavior: capture math, timing grading, retry/flee routing, recap, copy, or BallShake's timer durations. The visible shake animation (WR-02 / D-05 / D-30 visuals) is DEFERRED to Phase 8 — do not implement it here. Info items IN-01…IN-04 are out of scope.

<objective>
Fix the GradeFlash→BallShake ordering bug: `EncounterOverlay`'s `gradeFlashDone` React state is reset only in a `useEffect` after paint, so after the first GradeFlash completes it stays `true` through failBeat/timing; every subsequent throw's first shake paint mounts BallShake before GradeFlash, inverting D-14. Replace the overlay-owned flag with a `ShakeSequence` child component keyed on throw identity that owns its own `flashDone` state — reset happens via remount, before paint, structurally immune to leaks. Add the missing regression test covering the SECOND consecutive throw. Also add the `stage === 'timing'` invariant to `registerThrow` (WR-03) with a no-op unit test.

Purpose: D-14 is a locked decision and a verification blocker — grade feedback must precede outcome on every throw for the timing minigame to teach timing (CATCH-02) and for retries to read correctly (CATCH-04).
Output: `ShakeSequence` component, slimmed `EncounterOverlay`, new `EncounterOverlay.test.tsx` regression suite, guarded `registerThrow` with test.
</objective>
